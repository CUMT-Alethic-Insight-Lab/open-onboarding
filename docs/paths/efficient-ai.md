# 小模型与高效 AI：同口径比较质量与资源

**入口**：ML-03/08、DL-03/05；**出口**：在明示硬件上交付质量—大小—内存—延迟对照；**状态**：内容完成，待试走。

**小模型不等于模型压缩**：小模型可从零设计/训练；压缩从已有模型出发。可训练参数少不代表总参数、激活或延迟低；LoRA 是参数高效适配，量化是数值表示/执行选择，二者阶段与目标不同。

统一报告：数据与拆分、训练预算、模型/权重精度、参数量与文件大小、设备/线程、batch、预热、测量次数、延迟分布、内存口径、准确率及失败样例。理论 FLOPs/MACs 是指标之一，不是部署结论。

## EA-1 从零设计紧凑模型

- **前置**：DL-01、DL-03、DL-05。
- **目标**：能在目标硬件约束下权衡宽度、深度、参数量、计算和激活。
- **为什么在这里学**：紧凑架构与压缩已有模型是不同设计问题。
- **指定材料**：必学 [MobileNetV2](https://arxiv.org/abs/1801.04381)、[EfficientNet](https://arxiv.org/abs/1905.11946)；推荐 [PyTorch profiler](https://docs.pytorch.org/tutorials/recipes/recipes/profiler_recipe.html)。
- **学习动作**：区分参数量、FLOPs、MACs、权重/激活内存、吞吐、单请求延迟和功耗；比较深度可分离卷积、宽度/深度/分辨率缩放，不把复合缩放当固定最优公式。
- **最小实践**：同数据/seed/epoch 设计两种宽度 CNN 或小 Transformer；固定 batch 测准确率、状态大小、延迟和内存。
- **完成标准**：能解释哪项成本来自权重、激活或算子，为什么较小模型未必较快；结论只适用于明示环境。
- **卡住时**：回 DL-01 算形状/参数、DL-03 固定训练预算；先建立未优化基线再改一个变量。
- **下一步**：EA-2 或 EA-3。
- **资源要求**：CPU 小模型；移动端功耗测量为选做，未测须注明。

### EA-1 检查表

| 维度 | 要回答的问题 |
| --- | --- |
| 架构 | 宽度、深度、卷积分组、注意力长度怎样改变归纳偏置与成本 |
| 参数/计算 | 参数少是否仍激活大、算子不友好或内存访问昂贵 |
| 训练 | 两模型是否同数据、同预算、同调参机会；小模型是否需要蒸馏另行说明 |
| 服务 | batch=1 延迟与批量吞吐是否分开，目标设备是否有对应高效算子 |

## EA-2 从已有模型压缩与适配

- **前置**：EA-1；DL-03 的完整训练闭环。
- **目标**：理解蒸馏、结构化/非结构化剪枝、PTQ/QAT、weight-only/激活量化与 LoRA 的机制差异。
- **为什么在这里学**：方法名称不决定真实质量、大小或速度，硬件支持是约束的一部分。
- **指定材料**：必学 [Distilling the Knowledge in a Neural Network](https://arxiv.org/abs/1503.02531)、[torchao 官方文档](https://docs.pytorch.org/ao/stable/)；推荐 [PyTorch Pruning](https://docs.pytorch.org/tutorials/intermediate/pruning_tutorial.html) 与 [Quantization](https://docs.pytorch.org/docs/stable/quantization.html)。
- **学习动作**：蒸馏比较 teacher/student logits 与 temperature；结构化剪枝移除真实通道，非结构化稀疏通常需要专用执行才体现速度；PTQ 在训练后校准/转换，QAT 在训练中模拟量化误差；LoRA 冻结基座并训练低秩增量。
- **最小实践**：运行 `python examples/efficient_ai.py`，比较同预算 baseline/compact 与 baseline 的 INT8 per-output-channel weight-only PTQ；检查精度、状态大小、RSS 采样与延迟。
- **完成标准**：说明量化粒度、激活是否量化、权重文件与实际执行差异；不能把权重位宽换算直接当吞吐提升。
- **卡住时**：先复现未压缩基线；质量下降检查校准/量化层与粒度，速度慢检查反量化、算子与 batch。
- **下一步**：EA-3。
- **资源要求**：本仓透明教学实现可 CPU；生产 torchao/硬件路径需另实测。

### EA-2 方法对照

| 方法 | 何时发生 | 主要改变 | 不能据此承诺 |
| --- | --- | --- | --- |
| 从零紧凑设计 | 架构与训练前 | 结构、参数与激活 | 任意硬件都快/准 |
| 蒸馏 | 学生训练阶段 | 教师信号与学生参数 | 无损、无需训练预算 |
| 剪枝 | 训练中/后 | 权重稀疏或真实结构 | 非结构化稀疏自动提速 |
| PTQ | 训练后 | 权重和/或激活数值表示 | 无校准损失、低位算子到处可用 |
| QAT | 训练过程中 | 模拟量化误差的优化 | 无需训练、部署格式任意 |
| LoRA | 适配训练阶段 | 低秩可训练增量，基座冻结 | 与量化同义、基座内存消失 |

## EA-3 小模型部署与权衡

- **前置**：EA-2。
- **目标**：能按 CPU/消费级 GPU/端侧约束选择格式与运行时，并写出权衡报告。
- **为什么在这里学**：模型文件、运行时、算子和硬件共同决定部署结果。
- **指定材料**：必学 [ONNX Runtime](https://onnxruntime.ai/)、[ExecuTorch](https://pytorch.org/executorch/) 与 [llama.cpp](https://github.com/ggml-org/llama.cpp) 的官方适用说明；推荐 [ONNX 模型导出](https://docs.pytorch.org/tutorials/beginner/onnx/intro_onnx.html)。
- **学习动作**：比较图导出/内核覆盖、CPU/GPU/NPU 后端、weight-only/激活量化、批处理/并发与 KV Cache；说明 ONNX 是交换格式，ONNX Runtime 是执行引擎。
- **最小实践**：选明确预算（如笔记本 CPU、batch=1、内存上限），部署一个小模型或提出可执行配置，记录准确率、模型大小、峰值内存口径、P50/P95 延迟和吞吐。
- **完成标准**：报告能解释为何在该约束下选此方案，并给出至少一个失败条件/回退方案；未实测的设备标待实际测试。
- **卡住时**：回 EA-2 检查模型格式与算子；用最小单请求 profile，先排除转换/预热/IO，再改并发。
- **下一步**：接 Infra 服务、端侧项目或评测路径。
- **资源要求**：概念与教学示例 CPU 即可；ExecuTorch/消费级 GPU/真实端侧不是已完成验证。

## 同口径测量规范

1. **固定质量口径**：同测试集、预处理、batch 与指标；不同训练预算不能直接宣称架构更优。
2. **固定系统口径**：同设备、线程、运行时、精度与输入形状；先预热，测足够次数，报告中位数和尾延迟而非只报最好一次。
3. **内存分清口径**：权重理论大小、序列化文件、运行 RSS/显存峰值、激活峰值不同；采样 RSS 不是硬件峰值保证。
4. **报告真实结果**：本仓示例输出 JSON，保留环境/seed/测量说明；结果不能外推到其他模型或硬件。
5. **保留反例**：更小/更低位却更慢或更差是有效结论，先解释，不为“高效”标题删掉。

## 毕业任务

提交 baseline → 一种紧凑设计或压缩干预 → 一个目标部署选择的报告。必须含同口径指标表、误差分析、实际命令、版本、设备、测量方法与限制。推荐从本仓 CPU 示例开始；没有目标硬件时写“模拟配置/待实测”，不得声称端侧部署已验证。
